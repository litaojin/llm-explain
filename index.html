  2. Runtime 解析并检查参数，按注册表将名称映射到真正的函数实现。
  3. 函数返回后，程序用同一个调用标识封装 Tool 消息，模型后续据此回答。

为什么请求与返回结果都需要关联到同一次调用？

程序要知道每份结果对应哪个助手请求。本例请求 id=call-1，Tool 消息的 tool_call_id=call-1，使后续输入能正确配对。

观看时，追这三件事

  1. 应用先配置连接，再获取文件、搜索、业务工具的说明，并更新可用 Tools。
  2. 下一次模型调用看到更新后的声明，选择已接入的工具；应用通过 MCP 取得结果。
  3. 结果仍回到 Context，模型仍按原 Loop 继续；增加的是工具能力，不是模型参数。

新接入 MCP 搜索工具后，变化的是模型权重还是应用提供的工具声明？

变化的是应用可调用的能力及提供给模型的工具声明，不是模型权重。MCP 用标准协议对接外部工具，不替代 Agent Loop。

别混淆：工具需应用配置连接，可本机也可远程，并非自动接入。MCP 不只提供工具；本课不展开其他能力、Client/Server、报文或传输。所有连接和结果均为预设示意。

读完以后，先分清这四组关系。

生成 ≠ 训练：追加 token 改变输入，训练更新参数。
BP ≠ 参数更新：BP 求梯度，优化器用梯度改参数。
初始嵌入 ≠ 上下文表示：固定参数与相同 ID 下查出的嵌入不变，后续表示可随上下文变化。
模型请求 ≠ 工具执行：Runtime 执行工具、累积 Context；MCP 扩展工具接入，不改变模型参数。

需要时，再看术语速查 ＋
Token
模型处理的文本片段；不固定等于一个汉字、一个词或一个字符。
参数 / 权重
训练中被调整的数值；推理时在本系列演示中保持固定。
正向传播
使用当前参数，从输入逐层算出预测。
Loss
用选定的损失函数衡量预测与目标的不一致。
梯度
Loss 对参数等变量的局部变化率；不是参数的新值。
BP
反向传播：沿计算图使用链式法则，计算梯度。
优化器
利用梯度执行参数更新。最简单的例子是 SGD，学习率决定更新步幅。
预训练 / SFT
这里先以原文预测目标理解预训练，再以指令—示范回答理解监督微调。
Embedding
按 token ID 查出的初始向量表示；嵌入表也是可学习参数。
上下文表示
后续网络结合可见上下文计算出的表示，不等于改写嵌入表。
Attention
按权重汇集可见位置的 value 信息，参与表示更新；不等于整个 Transformer。
Agent Loop
Context、模型、Runtime 与工具协作，执行后追加结果并再次调用模型，或返回最终回答。
Context
一次模型调用实际收到的输入；历史由程序保存并重新提供，不是永久模型记忆。
MCP
可用于标准化接入外部工具的协议；工具需要应用配置连接，不改变模型参数。MCP 也支持工具之外的能力。
